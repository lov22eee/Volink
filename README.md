# Volink

**가까운 곳에서, 함께 만드는 작은 변화.**

Volink는 지역 주민이 짧은 봉사활동을 직접 열고, 주변 이웃과 함께 참여하는 웹 플랫폼입니다. **2~10명·3시간 이내** 활동을 중심으로 신청, 정원·대기열, 현장 출석, 완료 기록과 안전 관리를 연결합니다.

> 활동 기록은 **플랫폼 내부 기록**입니다. 공식 봉사실적으로 인정되지 않으며 자원봉사 종합보험이 적용되지 않습니다.

### 화면만 확인하고 싶다면

`docs/ui/Volink_서비스화면.html`은 **현재 React 화면을 그대로 묶은 단일 파일**입니다. 저장한 파일을 더블클릭하거나 Chrome·Edge에 끌어다 놓으세요. 서버·MySQL·Node 설치 없이 활동 찾기, 상세, 만들기, 내 활동, 로그인, 회원가입을 직접 볼 수 있습니다.

활동 정보는 파일에 포함된 예시입니다. 공개 화면에는 서비스 메뉴만 두고, 하단에 예시 활동·신청 및 로그인 미제공 안내를 표시합니다. 학교·팀원·주차·발표·개발 진행 상황은 서비스에 넣지 않습니다.

화면 코드를 변경한 뒤에는 `frontend/`에서 `npm run ui:export`로 다시 만드세요. 외부 연결 없이 작동하는지 검증하는 브라우저 테스트도 포함됩니다.

주소로 접속해 발표하려면 [AWS 화면 공개 안내](docs/aws-ui-preview.md)를 따르세요. S3·CloudFront에 HTML 하나를 올리는 방식이며 전체 서버·DB 배포 없이 현재 화면을 공개합니다. [화면 파일 검증 결과](docs/verification-offline-ui.md)도 기록했습니다.

현재 공개 경로는 [GitHub Pages](https://lov22eee.github.io/Volink/)입니다. 화면 변경을 main에 푸시하면 자동 배포하도록 구성했습니다. 배포 결과는 [Actions](https://github.com/lov22eee/Volink/actions/workflows/pages.yml)에서 확인합니다. 처음 설정하는 방법은 [배포 안내](docs/github-pages-ui.md)를 참고하세요.

## 현재 구현 상태

### 지금 동작합니다 (2026-10-21 기준 · 4주차 + 4주차 보완)

- **홈(4주차 보완 5):** 첫 화면. 소개 문구 + ‘내 주변 활동 찾기 / 활동 만들기’, 로그인하면 내 활동 요약, 실제 숫자(모집 중·이번 주말·1365 활동), 위치를 허락한 적 있으면 가까운 활동 3개(없으면 모집 중 3개), 참여 방법 4단계와 공식 실적·보험 안내. 메뉴는 홈 / 활동 찾기 / 활동 만들기 / 내 활동.
- **회원가입·로그인:** 일반·기관회원 가입이 실제로 저장됩니다. 비밀번호는 BCrypt로 암호화하고, 로그인하면 30분짜리 JWT와 14일짜리 HttpOnly 쿠키를 받습니다. 새로고침해도 로그인이 유지되고, 로그아웃하면 쿠키가 무효가 됩니다.
- **서버 검사:** 만 14세 미만 가입 거부, 가입 요청에 관리자 역할을 넣어도 일반 회원으로 저장, 같은 이메일 중복 거부, 로그인 5회 연속 실패 시 1분 제한.
- **활동 개설 저장:** 로그인한 회원이 활동을 등록하면 서버가 화면과 같은 규칙(정원 2~10명, 30~180분, 24시간 뒤~60일 안, 06:00~22:00)을 다시 검사하고 저장합니다.
- **위험도 검사:** 위험 단어·분야·종료 시각으로 바로 공개(LOW) / 관리자 검토(REVIEW) / 등록 불가(BLOCKED)를 나누고 결과와 이유를 화면에 보여줍니다. 등록 불가 활동은 저장하지 않고, 검토 활동은 승인 전까지 목록과 상세에서 숨깁니다(본인·관리자만 보임).
- **기관회원:** 기관 확인 전에는 기관 주관 활동을 열 수 없고, 관리자가 승인하면 기관 이름으로 열 수 있습니다.
- **관리 화면:** 관리자 로그인 시에만 ‘관리’ 메뉴가 생기며 기관 확인·검토 활동을 승인하거나 사유를 적어 반려합니다. 모든 처리는 `admin_actions`, 활동 상태 변경은 `activity_logs`에 기록합니다.
- **내 활동:** 내 정보(회원 유형·관심 분야·기관 상태)와 개설한 활동의 공개 상태·검토 이유·반려 사유를 보여줍니다.
- **활동 찾기:** 실제로 공개된 활동(‘모집 중’)과 예시 활동 3건을 함께 보여주며 검색어·날짜(오늘·이번 주·주말)·시간대(오전·오후)·분야·유형 필터가 둘 다에 적용됩니다.
- **시연 계정:** 개발 환경에서만 11명의 시연 인물이 로그인 계정이 됩니다(`{코드}@demo.volink.kr`, 비밀번호는 커밋하지 않는 `.env`의 `DEMO_ACCOUNT_PASSWORD`).
- **내 주변 찾기(4주차·보완):** 처음 들어오면 ‘내 주변 활동을 찾을까요?’를 한 번 묻고(허용했다는 사실만 브라우저에 기억해 다음부터는 바로 지도로 시작, 위치 자체는 저장 안 함), 위는 ‘내 주변’(지도 + 가까운 5개), 아래는 ‘모든 모집글’(거리순 카드)로 보여 줍니다. 내 위치 또는 직접 고른 지역(동네·역·건물 이름 검색)을 기준으로 반경 1·3·5·10·20km 안의 활동을 지도+목록으로 가까운 순으로 보여줍니다. 거리와 대략 이동 시간(걸어서/차로 몇 분, 직선거리 계산)을 표시하고, 고른 반경 안에 없으면 3→5→10→20km로 스스로 넓힙니다. 지도 핀을 누르면 미리보기가 뜨고, Kakao 지도에서 지도를 옮기면 ‘이 지역에서 다시 찾기’가 나옵니다. 내 위치는 그 검색에만 쓰고 저장·기록하지 않습니다.
- **글 수정·삭제(4주차 보완 2):** 내가 만든 활동 상세에 ‘수정하기·삭제’가 보입니다. 신청자가 없고 시작 전이면 전부 고칠 수 있고, 고칠 때 위험도 검사를 다시 합니다(위험 단어면 저장 안 함, 검토 대상이면 다시 관리자 확인). 신청자가 생기면 소개·만나는 곳만 고칠 수 있고 삭제는 막힙니다(신청은 5주차). 삭제한 글은 기록만 남고 모든 목록에서 사라집니다.
- **위험 단어 보완(4주차 보완 2):** 띄어쓰기를 무시하고 비교해 ‘전기 배관 작업’, ‘전기배관’도 잡습니다. 등록 불가에 배관·전선·고압·용접, 관리자 검토에 전기·가스를 더했습니다(V5.2).
- **장소 검색·분류(4주차 보완):** 활동 만들기에서 장소 칸의 돋보기를 누르면 ‘장소 찾기’ 창이 열리고 Kakao 장소 검색 또는 지도 가운데 핀 주변 장소에서 고릅니다. 서버가 Kakao 분류로 공원·카페·식당·도서관·공공기관은 바로 공개, 요양·병원·반려동물·학교 등은 관리자 검토, 주유소·술집 등은 고를 수 없게 나누고(`docs/rules.md` 장소 분류), 결과에 서명해 브라우저가 장소·분류를 바꾸지 못하게 합니다. Kakao REST 키가 없으면 관리자가 좌표를 넣은 장소만 고릅니다.
- **활동 만들기 화면(4주차 보완):** 장소 칸 하나 + 검색 창, ‘일정’ 카드(날짜 먼저 → 굴리는 시작 시간 선택 06:00~21:30·10분 단위)와 ‘활동 시간’ 카드(22:00 전에 끝나는 길이만 10분 단위로 표시, 끝나는 시각 함께), 정원 드롭다운, **준비물 버튼**(장갑·집게·봉투·물·모자·편한 신발을 눌러 켜고, 직접 추가, 그중 모집자가 나눠 주는 것 표시 · 최대 6개 · 분야별 기본값), 자주 하는 활동 불러오기, 오른쪽 미리보기와 ‘바로 공개/관리자 확인’ 예상 안내. 활동 상세에는 ‘챙겨 올 것 / 모집자가 준비해요’ 칩, 목록 카드에는 2개 + 나머지 개수로 보입니다. 준비물 이름도 위험 단어 검사에 들어갑니다(예: 사다리 → 등록 불가).
- **1365 봉사활동 함께 보기(4주차 보완):** 행정안전부 봉사참여정보서비스(공공데이터포털) 키가 있으면 지도 위치의 시·군·구 1365 활동을 받아 ‘1365 활동’으로 같은 지도·목록에 보여주고, ‘자세히’를 누르면 Volink 안에서 요약 창(기관·장소·기간·모집·분야 + 1365에서 신청하기·지도에서 보기·링크 복사)을, ‘1365에서 신청 ↗’은 새 탭으로 1365 그 활동 페이지를 엽니다. 신청·실적·보험은 1365 기준이며 Volink는 정보만 보여줍니다. 담당자 이름·전화·이메일 등 연락처는 저장·표시하지 않습니다. 키가 없으면 이 부분은 보이지 않습니다.
- **공간 인덱스:** 활동 위치를 `activity_locations.location`(POINT, SRID 4326)에 두고 공간 인덱스로 먼저 좁힌 뒤 구면 거리로 정확히 거릅니다. 검토 중(REVIEW)·반려 활동은 거리 검색에도 나오지 않습니다.
- **장소 좌표 입력:** 관리자 화면 ‘장소 좌표’에서 지도 앱의 좌표(위도, 경도)를 붙여넣고 만남 지점을 적으면 그 장소의 기존·새 활동이 지도와 거리 검색에 나옵니다. 처리 내용은 `admin_actions`에 남습니다.
- **지도:** Kakao 지도 키(`VITE_KAKAO_JS_KEY`)가 있으면 Kakao 지도에 핀·검색 반경을 그립니다. 키가 없으면 좌표의 상대 위치만 그린 간단한 그림으로 대신합니다(실제 지도 아님).
- Flyway가 V1~V5와 V5.1(4주차 보완: 검색 장소 저장·만나는 곳·준비물·1365 캐시), V5.2(위험 단어 추가·삭제 상태)를 적용합니다. 재실행 시 데이터와 이력을 보존합니다.

### 아직 구현하지 않았습니다

참가 신청·승인·대기열·알림(5주차), 배포 서버에 Kakao·공공데이터 키를 넣은 뒤 실제 지도·장소 검색·1365 응답 확인(이 개발 환경에서는 두 서비스에 접속할 수 없어 확인하지 못함), 1365 조건 저장·새 활동 알림(5주차 알림과 함께), QR·위치 체크인·완료 기록(6주차), 신고·증빙·이의제기·제재·추천(7주차), 관심 분야 수정 화면(서버 API만 있음). **GitHub Pages는 서버 없이 예시 데이터만 담은 미리보기**라서 가입·로그인·저장이 되지 않습니다. 실제 동작은 배포 서버 https://3-104-31-169.sslip.io 에서 확인합니다.

> Kakao REST 키가 없으면 장소는 관리자가 등록한 후보 3곳에서만 고릅니다. 장소 분류는 Kakao 카테고리로 정하는 보조 수단이며 현장 이용 허가를 확인한 것이 아닙니다. 위험 단어 검사는 위험 가능성을 골라내는 보조 수단이며 활동이 안전하다고 보증하지 않습니다.

## 실행하기

### 1. 저장소 준비

처음 사용하는 PC:

```bash
git clone https://github.com/lov22eee/Volink.git
cd Volink
```

이미 내려받은 PC는 **기존 변경을 먼저 확인**합니다.

```bash
git status
git switch main
git pull --ff-only origin main
```

미커밋 변경이나 원격과 갈라진 커밋이 있으면 보존·통합한 뒤 진행하세요. `reset --hard`나 force push로 맞추지 않습니다.

### 2. 로컬 설정과 의존성 설치

저장소 최상위 `Volink/`에서:

```bash
./scripts/setup-env.sh
cd frontend
npm ci
cd ..
```

`setup-env.sh`는 무작위 로컬 DB 비밀번호를 **Git에서 제외된 `.env`**에 생성합니다. 기존 `.env`는 덮어쓰지 않습니다. 직접 설정하려면 `.env.example`의 변수명을 참고하고, 비밀번호를 비워 둔 상태로 DB를 시작하지 마세요.

| 변수 | 기본값·설정 | 설명 |
|---|---|---|
| `MYSQL_DATABASE` | `volink` | DB 이름 |
| `MYSQL_USER` | `volink` | 앱용 DB 사용자 |
| `MYSQL_PASSWORD` | 스크립트가 생성 | 앱용 DB 비밀번호 |
| `MYSQL_ROOT_PASSWORD` | 스크립트가 생성 | 로컬 MySQL 관리 비밀번호 |
| `MYSQL_PORT` | `3307` | PC에서 DB에 접근하는 포트 |
| `SERVER_PORT` | `8080` | 백엔드 포트 |
| `DB_HOST` | 기본 `127.0.0.1` | 별도 DB 이용 시 설정 |
| `JAVA_HOME` | Java 21 JDK | 여러 JDK 설치 시 명시적으로 지정 |
| `JWT_SECRET` | 스크립트가 생성 | 로그인 토큰 서명 키(Base64 32바이트). 비우면 서버를 껐다 켤 때마다 바뀜 |
| `DEMO_ACCOUNT_PASSWORD` | 스크립트가 생성 | 개발 환경 시연 계정 11명의 비밀번호. 비우면 시연 계정을 만들지 않음 |

기존 `.env`가 있으면 `./scripts/setup-env.sh`가 **빠진 값만 추가**하고 기존 값은 바꾸지 않습니다. Kakao·AWS 키는 아직 필요 없습니다. 시연 계정 비밀번호는 `.env`에서 확인하고 화면·문서·채팅에 붙여넣지 마세요. 개발 서버는 기본적으로 PC의 루프백에만 바인딩합니다. Vite의 API 프록시는 기본 백엔드 `8080`을 사용하므로 포트를 바꾸면 프록시와 검증 스크립트도 함께 조정해야 합니다.

Codex 클라우드처럼 HTTPS 프록시가 있는 환경에서만 추가 실행:

```bash
./scripts/configure-cloud.sh
```

이 명령은 제공된 프록시와 CA를 Maven에 연결합니다. 인증서 검증을 끄지 않습니다. `.cache/`의 로컬 설정은 커밋하지 않습니다.

클라우드 기본 이미지에 Java 실행환경만 있고 `javac`가 없다면, Debian 클라우드 전용 보완 명령으로 전체 JDK를 설치합니다.

```bash
./scripts/install-cloud-jdk.sh
```

서명된 Debian 저장소의 패키지를 검증해 Git에서 제외된 `.tools/`에 추출합니다. 이 프로젝트의 백엔드 스크립트가 해당 JDK를 사용하므로 이후 작업에서도 유지됩니다. 개인 PC에서는 운영체제에 맞는 Java 21 JDK를 설치하세요.

### 3. 전체 서비스 실행

```bash
./scripts/start-dev.sh
./scripts/check-dev.sh
```

스크립트는 MySQL 준비 → 백엔드 빌드·시작 → 프론트엔드 시작 → 연결 확인 순으로 실행합니다. 첫 Maven 설치·빌드는 시간이 걸릴 수 있습니다. `check-dev.sh`는 화면 프록시를 거쳐 실제 API와 DB를 확인합니다.

일반 개발자 PC에서는 브라우저에서 `http://127.0.0.1:5173`에 접속합니다. **클라우드 온보딩 UI는 로컬 주소를 여는 웹 미리보기를 제공하지 않습니다.** 발표는 팀 PC에서 같은 명령으로 실행하세요.

### 따로 실행할 때

DB · 저장소 최상위:

```bash
docker compose up -d --wait db
```

백엔드 · 저장소 최상위:

```bash
./scripts/backend.sh spring-boot:run
```

프론트엔드 · 별도 터미널:

```bash
cd frontend
npm run dev
```

서버 준비 확인은 `GET /actuator/health`의 `UP`, `GET /api/project/status`의 `database: UP`입니다. API 목록과 응답 범위는 [구조 문서](docs/architecture.md#현재-api)를 참고하세요.

### DB 초기화·시연 데이터

첫 백엔드 시작 시 Flyway가 `V1__core_schema.sql`, `V2__demo_catalog.sql`, `V3__week2_members_safety_schema.sql`, `V4__week3_auth_activity.sql`을 적용합니다. 수동 SQL 실행은 필요 없습니다. DB는 Docker의 `volink_mysql-data` 볼륨에 유지되며 저장소 안에 DB 파일을 만들지 않습니다.

**기존 V1~V4를 수정하지 말고 새 `V5__...sql`을 추가하세요.** DB 비밀번호를 바꾸어도 이미 생성된 DB 사용자 비밀번호가 자동 변경되지는 않습니다. 기존 DB를 보존하면서 사용자 비밀번호를 변경해야 합니다.

### 종료·문제 확인

```bash
./scripts/stop-dev.sh       # 이 스크립트가 시작한 화면·서버만 종료
docker compose stop db      # 필요할 때 DB 중지 · 데이터 보존
```

- 실행 로그: `.run/backend.log`, `.run/frontend.log`
- DB 상태: `docker compose ps`, `docker compose logs db`
- 포트 충돌: 기존 프로세스를 확인한 뒤 이 프로젝트가 시작한 프로세스만 종료
- Maven 다운로드 실패: Java 21, 프록시·CA 설정, 네트워크를 확인
- DB 연결 실패: Docker 상태, `.env`와 기존 DB 사용자 비밀번호 일치 여부를 확인

일반 개발·인수인계에서 DB 볼륨 삭제 명령을 사용하지 않습니다.

## 테스트

Docker를 켜고 다음 명령을 실행합니다.

```bash
# 실제 별도 MySQL 컨테이너로 DB·API·제약 검증
./scripts/backend.sh test

# 프론트 타입 검사 및 배포용 빌드
cd frontend
npm run build
cd ..

# 실행 중인 전체 서비스 기능 확인
./scripts/check-dev.sh
```

브라우저 테스트는 전체 서비스가 실행 중이어야 합니다.

```bash
cd frontend
npx playwright install chromium
npm run test:e2e
```

클라우드의 기존 Chromium을 사용할 때는 설치 대신:

```bash
cd frontend
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

브라우저 테스트는 가입·로그인·개설·관리·내 주변 찾기 흐름과 모바일 캡처(`week-04-*.png`, 이번 주차 이름)를 `docs/screenshots/`에 갱신합니다. UI 수정 후 변경된 캡처도 검토하고 전달하세요. 테스트 결과는 주차별 검증 기록([1주차](docs/verification-week-01.md) · [2주차](docs/verification-week-02.md) · [3주차](docs/verification-week-03.md) · [4주차](docs/verification-week-04.md))에 구분해서 적습니다. 테스트 케이스 전체 목록은 [test-cases.md](docs/test-cases.md)입니다. Docker 데몬이 꺼져 있으면 백엔드 테스트가 “Docker 환경 없음”으로 실패하니 먼저 켜세요.
