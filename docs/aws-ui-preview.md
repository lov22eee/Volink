# AWS에서 현재 화면 공개하기

지금 구현한 React 화면만 발표용 HTTPS 주소로 공개하는 방법입니다. 전체 서비스 서버나 DB를 배포할 필요 없이 **S3 + CloudFront**를 사용합니다. 화면과 시연 데이터가 들어 있는 `index.html` 하나만 올립니다.

## 올릴 파일

`frontend/`에서 `npm run ui:export`를 실행합니다. 생성된 `docs/ui/Volink_서비스화면.html`을 `index.html`로 이름을 바꿔 업로드합니다. React 코드를 수정했으면 다시 생성한 파일로 교체합니다.

## AWS 콘솔에서 설정하기

1. **S3**에서 일반 버킷을 만듭니다. 버킷 이름은 고유해야 합니다. 퍼블릭 액세스 차단은 켜 둡니다.
2. 버킷의 최상위 경로에 `index.html`을 업로드합니다. 콘텐츠 유형은 `text/html`입니다. 저장소 전체나 `.env`를 업로드하지 않습니다.
3. **CloudFront**에서 배포를 만듭니다. 원본은 위 S3 버킷을 선택하고, **원본 액세스 제어(OAC)**를 사용합니다. S3 정적 웹사이트 엔드포인트가 아닌 버킷 원본을 사용합니다.
4. CloudFront가 제공하는 버킷 정책을 S3의 권한 → 버킷 정책에 적용합니다. 해당 CloudFront 배포에만 읽기 권한을 줍니다.
5. 기본 루트 객체는 `index.html`, 뷰어 프로토콜 정책은 **Redirect HTTP to HTTPS**로 설정합니다. 사용자 정의 도메인은 필요하지 않습니다.
6. 배포가 완료되면 CloudFront의 `https://….cloudfront.net` 주소를 브라우저에서 엽니다. 활동 찾기·상세·만들기·내 활동·로그인·회원가입을 눌러 확인합니다.

화면은 `#/create` 등 해시 경로를 사용하므로 별도의 SPA 오류 페이지 설정이 필요하지 않습니다. 시연 데이터는 파일 안에 포함되며 실제 신청·로그인은 이후 개발 범위입니다.

## 화면 업데이트와 비용

새 `index.html`을 같은 S3 경로에 업로드하고 CloudFront에서 `/index.html`과 `/` 경로를 무효화해 최신 화면을 확인합니다. 발표가 끝나 공개가 필요 없으면 CloudFront 배포를 비활성화한 후 삭제하고, S3 객체·버킷도 삭제할 수 있습니다.

요금은 AWS 계정의 플랜과 사용량에 따라 달라집니다. 생성 전에 콘솔의 적용 요금을 확인하고 AWS Budgets에 예산 알림을 설정하세요. 무료라고 가정하지 않습니다.

사용자는 아직 사용할 AWS 계정이 없다고 확인했습니다. 실제 버킷·배포를 생성하지 않았습니다. 환경 내부의 AWS 설정 파일 존재 여부는 사용자의 배포 계정 연결을 뜻하지 않습니다. GitHub 연동은 저장소 접근을 제공하며 AWS 계정 권한을 자동으로 제공하지는 않습니다. 인증키를 채팅이나 GitHub에 올리지 마세요.
