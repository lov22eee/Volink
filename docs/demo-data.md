# 시연 데이터 · 2주차 갱신

## 장소 후보

학교: **경동대학교**. 캠퍼스가 여러 곳이므로 현재 후보는 **양주 메트로폴캠퍼스 생활권 기준**입니다. 실제 소속 캠퍼스가 다르면 2주차에 장소를 바꿉니다.

| 번호 | 장소 후보 | 활용 시안 | 확인할 사항 |
|---|---|---|---|
| 1 | 옥정중앙공원 | 가벼운 공원 환경 정화 | 정확한 만남 지점·좌표·활동 허용 여부 |
| 2 | 독바위공원 | 산책로 플로깅 | 정확한 위치·학교에서의 이동 거리·이용 조건 |
| 3 | 회암사지 역사공원 | 허용된 공원 구역 환경 정화 | 유적 보호구역 제외·관리기관 이용 조건 |

현재 좌표는 **미확인**이며 임의 좌표를 넣지 않았습니다. 장소를 검증하거나 실제 활동 허가를 받았다고 주장하지 않습니다. 화면의 그림은 지도 아닌 UI 일러스트입니다.

## 장소 확정 상태 · 2026-10-11

**장소는 아직 확정하지 못했습니다.** 좌표·만남 지점·활동 허용 여부는 현장 확인이나 관리기관 문의가 필요해 저장소 작업만으로 확인할 수 없습니다. 임의 좌표를 넣지 않았고 `coordinate_status`는 계속 `UNVERIFIED`입니다. 담당자가 확인할 것: ① 실제 소속 캠퍼스가 양주인지 ② 세 장소의 만남 지점 주소·좌표(Kakao 지도) ③ 공원 관리 주체의 소규모 정화 활동 허용 여부. 확인되면 새 마이그레이션으로 좌표와 `VERIFIED`를 넣습니다(4주차 공간 검색 전까지).

**2026-10-16 변경(4주차):** 좌표는 마이그레이션 대신 **관리자 화면 ‘장소 좌표’**에서 넣습니다(지도 앱의 위도, 경도를 붙여넣기 + 만남 지점). 넣으면 `coordinate_status`가 `ENTERED`가 되고 그 장소의 활동이 지도·거리 검색에 나옵니다. `ENTERED`는 ‘좌표를 입력함’이라는 뜻이며 현장 이용 허가를 확인했다는 뜻이 아닙니다. 아직 실제 좌표는 입력하지 않았습니다(배포 서버에서 직접 입력 예정). 웹 검색으로는 독바위공원 지번(경기 양주시 옥정동 889, 공식 명칭 옥정제5근린공원)만 확인했습니다.

## 시연 계정 구성 정의 · 2주차 확정

계획서(모집자 2·참가자 6·관리자 1)에 제출 보고서의 기관회원 2명을 더해 **11명**으로 확정했습니다(V3).

| 코드 | 역할 | 회원 유형 | 시나리오 | 수 |
|---|---|---|---|---|
| `organizer-01`, `organizer-02` | USER | 일반 | 자율 활동 개설·승인·출석 처리 | 2 |
| `participant-01`~`participant-06` | USER | 일반 | 신청·대기·출석·완료 기록 (동시 신청·승격 시연에 6명 필요) | 6 |
| `institution-01` | USER | 기관 | 기관 확인 완료 · 기관 주관 활동 개설 | 1 |
| `institution-02` | USER | 기관 | 기관 확인 대기 · 주관 활동 개설 불가 | 1 |
| `admin-01` | ADMIN | 일반 | 위험 검토·기관 확인·신고 처리 | 1 |

`demo_personas`는 정의 테이블입니다. **3주차부터 개발(dev) 프로필에서만** 서버 시작 시 이 11명을 로그인 계정 `{코드}@demo.volink.kr`로 만듭니다(`DemoAccountSeeder`). 비밀번호는 커밋하지 않는 `.env`의 `DEMO_ACCOUNT_PASSWORD`이고, 값이 비면 만들지 않습니다. `institution-01`은 기관 확인 완료, `institution-02`는 확인 대기 상태로 만듭니다. 테스트 프로필과 운영에서는 만들지 않습니다. 시연 계정 생년월일은 만 14세 이상 가짜 날짜를 씁니다.

## 필요한 시연 데이터 항목

| 영역 | 항목 | 현재 |
|---|---|---|
| 장소 | 명칭·주소·만남 지점·공공장소 여부·좌표 | 후보 명칭·지역·검증 안내 |
| 사용자 | 시연 코드·표시명·역할·계정 상태 | 코드·표시명·페르소나 역할 |
| 활동 | 제목·설명·분야·장소·시간·정원·위험도·상태 | 읽기 전용 활동 템플릿 3건 |
| 참가 | 사용자·활동·상태·대기 순번·제안 마감 | 테이블 초안, 실제 데이터 없음 |
| 출석 | 방식·시각·반경 결과·수동 확인 사유 | 테이블 초안, 실제 데이터 없음 |
| 완료 | 확인자·확인시각·기록 상태·이의 제기 | 테이블 초안, 서비스 없음 |
| 안전 | 위험 키워드·신고·증빙·조치 사유 | 위험 키워드 초안 32개(V3), 신고·증빙·제재 테이블만 |
| 회원 | 회원 유형·생년월일·관심 분야·기관 | 테이블·제약(V3), 실제 데이터 없음 |

활동 시안의 인원 수는 고정된 **예시 인원**이며 실제 참가자가 아닙니다. 시연 날짜는 서버의 한국 날짜를 기준으로 3일 뒤를 표시하므로 매주 화면을 보여줄 수 있습니다.

## 적용과 보존

첫 서버 시작 시 Flyway가 V1 구조, V2 시연 데이터, V3 2주차 구조(회원 유형·기관·관심 분야·알림·신고·이의제기·제재·위험 키워드)를 적용합니다. 다시 시작하면 이미 적용된 마이그레이션은 재실행하지 않습니다. 시연 페르소나와 운영 사용자 테이블을 분리했으며 `users`, `activities`, `participations`는 초기 상태에서 비어 있습니다.

데이터 추가·변경은 새 마이그레이션을 작성합니다. 다른 담당자의 DB를 초기화하는 `docker compose down -v`를 일반 설치·실행 절차에 넣지 않습니다.
