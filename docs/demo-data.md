# 시연 데이터 · 1주차

## 장소 후보

학교: **경동대학교**. 캠퍼스가 여러 곳이므로 현재 후보는 **양주 메트로폴캠퍼스 생활권 기준**입니다. 실제 소속 캠퍼스가 다르면 2주차에 장소를 바꿉니다.

| 번호 | 장소 후보 | 활용 시안 | 확인할 사항 |
|---|---|---|---|
| 1 | 옥정중앙공원 | 가벼운 공원 환경 정화 | 정확한 만남 지점·좌표·활동 허용 여부 |
| 2 | 독바위공원 | 산책로 플로깅 | 정확한 위치·학교에서의 이동 거리·이용 조건 |
| 3 | 회암사지 역사공원 | 허용된 공원 구역 환경 정화 | 유적 보호구역 제외·관리기관 이용 조건 |

현재 좌표는 **미확인**이며 임의 좌표를 넣지 않았습니다. 장소를 검증하거나 실제 활동 허가를 받았다고 주장하지 않습니다. 화면의 그림은 지도 아닌 UI 일러스트입니다.

## 시연 계정 구성 정의

| 코드 | 역할 시나리오 | 수 |
|---|---|---|
| `organizer-01`, `organizer-02` | 본인 활동 개설·관리 | 2 |
| `participant-01`~`participant-06` | 신청·대기·출석·기록 | 6 |
| `admin-01` | 위험 검토·신고·조치 | 1 |

현재 `demo_personas` 테이블의 **역할 설계용 페르소나**입니다. 로그인 가능한 계정과 비밀번호는 만들지 않았습니다. 3주차에 인증을 구현할 때 USER/ADMIN 계정과 실제 비밀번호 해시를 로컬 또는 별도 시연 환경에서 구성합니다. 모집자 권한은 USER 역할과 활동 소유관계로 판단합니다.

## 필요한 시연 데이터 항목

| 영역 | 항목 | 현재 |
|---|---|---|
| 장소 | 명칭·주소·만남 지점·공공장소 여부·좌표 | 후보 명칭·지역·검증 안내 |
| 사용자 | 시연 코드·표시명·역할·계정 상태 | 코드·표시명·페르소나 역할 |
| 활동 | 제목·설명·분야·장소·시간·정원·위험도·상태 | 읽기 전용 활동 템플릿 3건 |
| 참가 | 사용자·활동·상태·대기 순번·제안 마감 | 테이블 초안, 실제 데이터 없음 |
| 출석 | 방식·시각·반경 결과·수동 확인 사유 | 테이블 초안, 실제 데이터 없음 |
| 완료 | 확인자·확인시각·기록 상태·이의 제기 | 테이블 초안, 서비스 없음 |
| 안전 | 위험 키워드·신고·증빙·조치 사유 | 2주차 이후 명세·데이터 준비 |

활동 시안의 인원 수는 고정된 **예시 인원**이며 실제 참가자가 아닙니다. 시연 날짜는 서버의 한국 날짜를 기준으로 3일 뒤를 표시하므로 매주 화면을 보여줄 수 있습니다.

## 적용과 보존

첫 서버 시작 시 Flyway가 V1 구조와 V2 시연 데이터를 적용합니다. 다시 시작하면 이미 적용된 마이그레이션은 재실행하지 않습니다. 시연 페르소나와 운영 사용자 테이블을 분리했으며 `users`, `activities`, `participations`는 초기 상태에서 비어 있습니다.

데이터 추가·변경은 새 마이그레이션을 작성합니다. 다른 담당자의 DB를 초기화하는 `docker compose down -v`를 일반 설치·실행 절차에 넣지 않습니다.
