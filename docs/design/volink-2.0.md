# Volink 2.0 화면 구현 기록

기준: 사용자가 2026-10-28에 확정한 Volink 2.0 UI 시안(홈·활동 찾기·활동 상세·신청·내 활동). 시안을 디자인의 기준으로 삼고 화면별로 구현한 뒤 사용자 승인을 받고 다음 화면으로 넘어갑니다. 백엔드·DB·API·배포는 바꾸지 않습니다.

## 진행

| 화면 | 상태 |
| --- | --- |
| 홈 | 구현 · 시안 비교 검수 (2026-10-28 1차) |
| 활동 찾기, 활동 상세, 신청, 빈자리 제안, 내 활동, 알림, 신청자 관리, 로그인·회원가입, 관리자 | 구현 · 시안 비교 검수 (2026-10-28 2차) |
| 활동 만들기·수정 | 시안 없음 → 같은 디자인 시스템으로 맞춤 |

시안과 구현을 나란히 둔 그림: `docs/screenshots/v2/compare-01.jpg`(홈) ~ `compare-11.jpg`(관리자).

## 공통 (`frontend/src/v2.css`)

- 아이보리 바탕(#F9F7F2), 흰 머리글·바닥글, 딥그린(#245E48) 로고·제목, 주요 버튼은 검정 알약 모양, 보조 버튼은 흰 알약 + 선.
- 글꼴: Pretendard를 직접 넣음(SIL OFL 1.1, `frontend/src/assets/fonts/Pretendard-OFL.txt`). 용량을 줄이려고 영문·기호와 자주 쓰는 한글 2,350자(KS X 1001)만 남긴 가변 글꼴(약 470KB). 그 밖의 글자는 기기 한글 글꼴로 보입니다. 오프라인 화면 파일에는 글꼴을 파일 안에 넣어 외부 요청이 없습니다.
- 머리글: 로고 · 가운데 메뉴(활동 찾기·활동 만들기·내 활동) · 오른쪽 아이콘. ‘홈’ 메뉴는 넓은 화면에서 화면 읽기용으로만 남기고(로고가 홈), 휴대폰 아래 탭바에는 보입니다.

## 홈 (`frontend/src/home.tsx`)

- 시안 구성 그대로: 큰 제목 히어로 → ‘어떤 봉사에 관심 있나요?’ 분야 버튼 → ‘이번 주, 함께할 활동’ 3개 → ‘처음이어도 괜찮아요.’ 안내 3단계.
- 분야 버튼은 실제 분야 3개(환경 정화·생활 지원·지역 돌봄)이고, 누르면 활동 찾기가 그 분야로 걸러진 채 열립니다(`#/explore?category=…`). 시안의 ‘동물·교육·복지’는 예시라 쓰지 않았습니다.
- 활동은 서버의 실제 모집글(오늘 이후)만 씁니다. 이번 주(오늘~6일 뒤) 활동이 없으면 제목이 ‘곧 열리는 활동’으로 바뀝니다. 정원이 차면 ‘대기 가능 · 정원 마감’.
- 이미지: 실제 활동 사진이 없으므로 **분야별 기본 커버**(그림)를 씁니다. 같은 분야라도 활동 번호에 따라 구도·색이 바뀌어 옆 카드와 겹치지 않습니다. 사진처럼 보이게 하지 않았습니다.
- 히어로 사진 자리: 시안은 현장 사진이지만 쓸 수 있는 실제 사진이 없어 분야 커버 3장 모음으로 대신했습니다. 사용권이 있는 사진을 주시면 바꿀 수 있습니다.
- 뺀 것: 모집 수 통계 카드, 내 요약, 내 주변 거리 목록(시안에 없음). 거리순 탐색은 활동 찾기에 그대로 있습니다.

## 2차 화면 (2026-10-28)

- **활동 찾기:** ‘FIND YOUR VOLUNTEER ACTIVITY’ 제목, 항상 보이는 둥근 검색창 + 검은 검색 버튼 + 필터, 분야 버튼(전체·환경 정화·생활 지원·지역 돌봄). 목록은 왼쪽 그림 + 상태·분야·제목·일시·장소·남은 자리 카드. 위치를 정하기 전에는 오른쪽 지도 자리에 ‘내 주변 활동을 찾을까요?’(위치 묻기)가 들어갑니다. 위치를 정하면 기존 실제 지도(Kakao 키가 있을 때)·반경·1365 활동·쪽 나눔이 그대로 동작합니다. 폰은 목록/지도 전환을 그대로 씁니다.
- **활동 상세:** 위쪽 분야 커버 → 상태·분야·유형 칩, 큰 제목 → ‘어떤 활동인가요?’ → ‘참여 전 알아두세요’(준비물·만나는 곳·안전·공식 실적 아님) → 진행 순서. 오른쪽 ‘참여 정보’ 상자에 일시·장소·확정 인원 막대·‘신청 후 모집자 승인을 기다려요’ 안내·검은 ‘참가 신청하기’ 버튼.
- **신청(시안 04):** 별도 확인 화면을 새로 만들지 않고, 같은 안내(승인 대기 설명)를 상세의 신청 상자에 넣었습니다. 라우트·API를 늘리지 않기 위해서입니다.
- **빈자리 제안(시안 06):** 내가 ‘빈자리 제안 받음’ 상태이면 상세 맨 위에 ‘기다리던 활동에 자리가 생겼어요!’ 영역이 나오고, 서버가 준 실제 응답 마감 시각, ‘참여할게요’ / ‘이번에는 참여하지 않을게요’ 버튼이 있습니다(기존 수락·거절 API).
- **내 활동:** MY VOLINK 제목, 이름·회원 유형·이메일·기관 확인 상태, 자리 제안이 있으면 맨 위 ‘지금 확인할 일’, 참여 확정·대기 중·승인 대기 3칸, ‘신청한 활동 / 내가 만든 활동’ 두 탭, 날짜 블록이 있는 목록. 기존 ‘활동 기록’ 탭(내용 없이 준비 중이던 칸)은 시안에 없어 뺐습니다(6주차 완료 기능과 함께 다시).
- **알림:** 제목 옆 ‘모두 읽음’, 안 읽은 알림은 연한 초록 카드, 안 읽은 빈자리 제안에는 검은 ‘제안 확인’ 버튼.
- **신청자 관리(모집자):** ORGANIZER 제목, 확정·승인 대기·대기열 3칸, 신청자 줄마다 아이콘·가린 이름·상태 칩·‘승인’(검정)·‘거절’(선) 버튼.
- **로그인·회원가입:** 왼쪽 연한 초록 소개 판, 오른쪽 ‘로그인 / 회원가입’ 전환, 둥근 입력칸, 검은 버튼. 회원가입의 개인 회원(일반회원)·기관 회원(기관회원) 선택 카드, 관심 분야 알약, 이용 안내 확인도 같은 모양입니다.
- **관리자:** ADMIN 제목, 카드마다 제목·‘관리자 전용’ 칩, 줄 단위 처리(사유 입력·승인·반려), 장소 좌표 입력.
- **만들기·수정:** 시안이 없어 같은 제목 형식(CREATE ACTIVITY)·검은 등록 버튼·초록 단계 번호로 맞췄습니다. 입력 규칙은 그대로입니다.

## 아직 없는 기능 (화면에 연결하지 않음)

- 시안의 **자동 확정 / 참여 재확인 대기열**은 아직 구현되지 않았습니다. 지금 있는 것은 모집자 승인, 정원이 차면 대기 순번, 빈자리 생기면 자리 제안 → 수락/거절, 1분 스케줄러(제안 만료·시작 2시간 전 대기 마감)입니다. 없는 버튼이나 가짜 신청 완료는 만들지 않았습니다.
- 관리자 시안의 ‘활동명 검색’ 표는 지금 관리 기능에 없는 검색이라 넣지 않았습니다.
- 히어로 사진: 이 개발 환경에서 사진 사이트(위키미디어 공용·Unsplash·Pexels)가 네트워크 정책으로 막혀 사용권 있는 사진을 받지 못했습니다. 분야 커버 모음을 유지합니다.

## 테스트에서 바꾼 것

- 버튼·탭 글자가 시안대로 바뀐 곳만 고쳤습니다: ‘자리 수락’ → ‘참여할게요’, ‘개설한 활동’ → ‘내가 만든 활동’, ‘활동 기록’ 탭 확인 제거. ‘참가 신청’·‘대기 신청’은 ‘참가 신청하기’·‘대기 신청하기’가 되어 기존 정규식 그대로 통과합니다.

## 관리자 화면 (2026-10-28)

- 관리자 계정은 **관리자 메뉴만** 봅니다: 대시보드(`#/admin`) · 기관 확인(`#/admin/organizations`) · 활동 검토(`#/admin/activities`) · 장소 관리(`#/admin/places`). 로그인하면 대시보드로 가고, 회원용 화면(홈·찾기·만들기·내 활동·알림) 주소로 들어오면 대시보드로 돌려보냅니다. 활동 상세는 검토용으로 열 수 있습니다(신청 버튼 없음). 화면 숨김과 별개로 서버도 관리자의 활동 개설·신청을 막고(`ActivityService`, `ParticipationService`), `/api/admin/**`은 관리자만 호출됩니다(`SecurityConfig`).
- 대시보드: 머리글은 관리 도구 형식(위치 · 제목 · 몇 시 기준 · 새로고침). 숫자 카드 4개(기관 확인 대기·활동 검토 대기·지금 모집 중·좌표 없는 장소, 누르면 해당 화면), 기관 회원가입 확인 요약(대기/승인/반려 막대, 오래 기다린 순 3건), 게시글 승인 요약(최근 3건과 검토 이유), 그래프 좌우 2개(앞으로 14일 모집 일정 막대 · 지난 14일 일별 참가 신청 꺾은선 + 지금 신청 상태 합계), 분야별 모집 중, 정원 채움 현황. 관리자 화면에서는 회원용 바닥글 안내를 숨깁니다.
- 새 API 1개(읽기 전용): `GET /api/admin/stats/applications?days=14` — 날짜별 참가 신청 수와 상태별 합계(`AdminService.applicationStats`, 테스트 `ParticipationIntegrationTest`). DB 변경 없음.
- 쓰는 기존 API: `GET /api/admin/organizations?status=PENDING|APPROVED|REJECTED`, `GET /api/admin/activities`(검토 대기 = DRAFT·REVIEW), `GET /api/activities`(공개 모집 중·시작 전), `GET /api/places`, 처리용 `POST …/approve|reject`, `PUT /api/admin/places/{id}`.
- 아직 API가 없어 **못 만드는 것**: 회원 수·가입 추이, 새 활동 등록 추이, 반려·종료된 활동 목록, 자리 제안 만료 건수, 1365 호출 수, 스케줄러 상태(B+안 job_runs). 화면에 빈 카드로 두지 않았습니다.
- 그림: `docs/screenshots/v2/admin-dash-d.jpg`, `admin-dash-m.jpg`, `admin-orgs-d.jpg`.
