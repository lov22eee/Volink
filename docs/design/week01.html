1주차 설계 정리

제출한 보고서의 네 가지 설계 내용을 한 페이지로 정리했습니다.

설계 초안 · 기능 구현 완료를 의미하지 않음
1. 서비스 흐름2. 회원·권한3. 화면 구조4. 데이터·API·테스트

01서비스 구조와 사용자 흐름

활동 개설→참가 신청→승인 / 대기→체크인→활동 완료·기록

정원을 넘으면 대기열로 이동하고, 빈자리가 생기면 순서대로 승격을 제안합니다.

브라우저 화면(React) → 서버 API(Spring Boot) → 데이터 저장(MySQL)

02회원 유형과 권한

회원 유형가능한 작업확인 조건
일반회원활동 탐색·참가, 자율 활동 개설본인 신청·기록, 자신이 개설한 활동만 관리
기관회원일반 참여, 기관 주관 활동 개설기관 확인·승인 완료 후 주관 활동 등록
관리자기관 승인, 위험 활동 검토, 신고·활동 관리관리자 권한과 처리 사유 확인

기관 확인 신청 → 관리자 검토 → 승인 또는 반려. 관리자 권한은 회원가입에서 선택할 수 없습니다.

04데이터·API·상태·테스트 설계

핵심 ERD · 개념 구조

기관과 사용자·활동의 연결은 설계 범위입니다. 실제 기관 테이블·승인 API는 아직 없으며, 상세 키와 제약은 다음주에 확정합니다.

주요 API 구조 · 예정 경로

구분경로 초안역할
인증POST /api/auth/signup, /api/auth/login회원가입 · 로그인
기관POST /api/institutions
PATCH /api/admin/institutions/{id}/approval		기관 확인 신청 · 관리자 승인
활동GET /api/activities, /api/activities/{id}
POST /api/activities		검색 · 상세 · 개설
참가POST /api/activities/{id}/participations
PATCH /api/participations/{id}/status		신청 · 승인 · 대기 · 취소
출석·완료POST /api/participations/{id}/check-in
POST /api/activities/{id}/complete		출석 확인 · 완료 처리
내 활동GET /api/me/activities본인 신청 · 개설 · 기록 조회

위 경로는 업무 API 설계 초안이며 실제 제공되는 API 목록이 아닙니다.

참가 상태 전환

신청 → 승인 또는 대기대기 → 승격 제안 → 승인승인 → 체크인 → 완료시작 전 취소 · 미출석 구분

시연 자료와 기본 테스트 계획

장소 후보: 옥정중앙공원 · 독바위공원 · 회암사지 역사공원. 일반·기관·관리자 역할별 시연 데이터를 준비하며 장소 이용 조건은 확인이 필요합니다.

  • 같은 활동에 중복 신청 시 거부
  • 동시 신청에도 정원 초과 방지
  • 다른 사람의 활동 관리 요청 거부
  • 미승인 기관의 주관 활동 등록 거부
  • 위험 분류에 따른 게시·검토·차단
  • 체크인 시간·위치와 완료 조건 확인

검증할 항목을 정리한 계획이며 테스트 통과 결과가 아닙니다.
