활동 카드는 서버가 MySQL에서 꺼내 준 데이터입니다. 입력칸의 빨간 오류는 브라우저가 먼저 검사합니다.

2. 지금 되는 것과 다음 주

지금 (2주차)
서버는 목록을 읽어 주고, DB는 규칙을 지킵니다. 입력 오류는 브라우저만 검사합니다.
3주차
로그인·가입·활동 저장 API를 만들고, 서버가 같은 규칙으로 다시 검사하고 위험도를 판정합니다.

활동 기록은 공식 봉사실적이 아니며 자원봉사 종합보험이 적용되지 않습니다.

3. 자동 테스트 14개 모두 통과

실제 MySQL을 새로 띄워 검사했습니다. GitHub에서도 main 합병 후 같은 테스트가 통과했습니다(Actions 실행 #9).

  • V1~V3 적용, 테이블이 ERD와 일치
  • 시연 데이터 한 번만 적용
  • DB 연결 시 활동 목록 응답
  • 상태 확인 · 로그인 미구현 표시
  • 쓰기·보호 경로 차단
  • 정원 2~10명만 허용
  • 활동 시간 3시간 이내
  • 같은 활동 중복 신청 차단
  • 수동 출석은 사유 필수
  • 생년월일 필수 · 관리자≠기관
  • 기관 승인·반려 사유 필수
  • 기관 주관 활동은 기관 필수
  • 신청 상태 값 제한
  • 신고·증빙·이의제기·제재 규칙

5. DB가 직접 막는 장면

규칙을 어긴 데이터를 넣으면 저장 전에 거부됩니다. 서버 코드에 실수가 있어도 마지막에 DB가 막습니다.
