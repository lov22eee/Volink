2주차 · 명세 확정

지난주 설계 초안을 실제 DB 구조와 규칙으로 굳혔습니다. 업무 기능은 아직 없습니다.

목차는 다음과 같습니다.

  1. 1 회원·권한
  2. 2 상태 흐름
  3. 3 입력 규칙 화면
  4. 4 데이터 구조
  5. 5 위험 키워드
  6. 6 남은 일

1. 회원은 셋, 기관은 확인 후 주관

관리자는 가입으로 만들 수 없습니다. 만 14세 미만은 가입할 수 없습니다.

일반회원자율 활동 개설신청·기록
기관회원확인 대기 → 확인 완료기관 주관 활동확인 전 주관 불가
관리자REVIEW 검토기관 확인·신고·제재사유 없이 조치 불가

2. 신청 한 건의 길

거절·재신청·보류 복원 규칙을 정했습니다. 제안 중인 자리도 정원에 넣습니다.

신청→확정→체크인→완료· 거절대기 → 제안 → 확정/만료취소노쇼보류 → 재개/무효

활동 만들기 8칸, 회원가입 10칸에 규칙과 문구를 붙였습니다. 서버 검사는 3주차입니다.

4. 데이터 구조 17개 테이블

V3로 9개를 더해 계획서 ERD 네 묶음을 채웠습니다. 실제 MySQL 백엔드 테스트 14개가 통과했습니다.

묶음테이블

활동 2activities, activity_locations
참가 4participations, check_ins, activity_records, activity_logs
안전·관리 6reports, report_evidences, appeals, sanctions, admin_actions, risk_keywords

5. 키워드는 거르는 도구일 뿐

키워드에 안 걸려도 안전하다는 뜻은 아닙니다. REVIEW는 관리자가 마지막에 봅니다.

금지 규칙→위험 키워드→관리자 확인(REVIEW)

6. 아직 안 된 것

로그인·가입 저장·위험도 판정·신청은 미구현입니다. 장소 좌표와 허용 여부는 미확인입니다.

3주 인증·개설·위험도→4주 위치 검색·첫 배포→5주 신청·대기열·알림→6주 체크인·완료→7주 신고·이의·제재·추천

활동 기록은 공식 봉사실적이 아니며 자원봉사 종합보험이 적용되지 않습니다.
