# 5주차 발표 · 2026-10-16 준비 → 2026-10-26 4주차 보완 반영 (최신)

5주차 코드는 5주차 브랜치에 있고 4주차를 먼저 합친 뒤 합칩니다. 시연은 시연 계정(모집자 1, 참가자 3)으로 하면 가입 없이 바로 됩니다.

## 화면 순서 (3분)

1. 참가자 2명 신청 → 모집자 신청자 목록에서 승인 → '확정 2 / 2명' (`week-05-applicants.png`)
2. 세 번째 참가자 신청 → '대기 1번'
3. 확정자 1명 취소 → 대기자 종 아이콘 알림 '빈자리가 생겼어요' (`week-05-notifications.png`)
4. 대기자 '자리 수락' → '참가 확정' (`week-05-offer.png`)

## 대본 (요지)

> 5주차에는 신청과 대기열을 만들었습니다. 승인할 때 서버가 활동을 잠그고 확정 인원을 다시 세기 때문에 정원을 넘을 수 없습니다. 정원이 차면 대기 순번을 받고, 누가 취소하면 대기 1번에게 자리를 제안합니다. 시간 안에 수락하지 않으면 다음 사람에게 넘어갑니다. 테스트에서 마지막 한 자리에 승인 10건을 동시에 보냈더니 처음에는 10건이 모두 확정되는 문제가 있었고, 원인(DB 격리 수준)을 찾아 1건만 확정되도록 고쳤습니다.

## 예상 질문

- **동시에 신청하면 어떻게 돼요?** 활동 행을 잠그고 한 번에 하나씩 처리합니다. 10건 동시 승인 테스트에서 1건만 확정됐습니다.
- **격리 수준이 뭐예요?** 같은 시간에 여러 작업이 DB를 볼 때 서로의 변경을 언제 보이게 할지 정하는 설정입니다. 기본값에서는 잠금 전의 오래된 숫자를 봐서, 커밋된 최신 값을 보는 READ COMMITTED로 바꿨습니다.
- **알림은 문자로 와요?** 아니요. 비용과 개인정보 때문에 화면 안 알림만 쓰고 30초마다 새 알림을 확인합니다.

# 4주차 발표 · 2026-10-21 보완 반영

4주차 코드(2026-10-16)와 4주차 보완(2026-10-21: 장소 검색·화면 개선·1365 연계)을 main에 합쳐 배포 서버에 반영한 뒤 보여줍니다. 반영 방법: PR 합치기 → 서버에서 `sudo bash /opt/volink/scripts/aws/set-keys.sh`(키 3개 입력 후 자동 재빌드). 발표 당일 직전에는 반영하지 않습니다.

**동작·미확인 구분:** 아래 1~6은 로컬에서 실제로 동작을 확인했습니다(Kakao 키 없이: 등록 장소 3곳·위치 그림). 카카오 지도는 AWS 서버에서 키를 넣고 표시되는 것을 사용자가 확인했습니다(2026-10-29). 카카오 장소 검색·1365 실제 응답은 서버에서 따로 확인해야 하며, 확인 전에는 “연결해 두었다”까지만 말합니다. 1365 화면 테스트는 가짜 응답으로만 했고 그 화면은 캡처로 쓰지 않습니다.

## 화면 순서 (3분)

0. 홈: 실제 모집 숫자·가까운 활동 3개·참여 4단계 → ‘내 주변 활동 찾기’ (`week-04-home.png`, 2026-10-22 추가)
1. 활동 찾기 → ‘내 주변 활동을 찾을까요?’ → **내 위치로 찾기** (`week-04-ask.png`)
2. 지도+목록, 카드의 ‘0.9km · 걸어서 12분’, 핀 누르면 미리보기 (`week-04-nearby.png`)
3. 멀리서 찾으면 ‘3km 안에는 없어서 5km까지 넓혔어요’ (`week-04-widen.png`)
4. 활동 만들기 → 장소 돋보기 → 장소 찾기 창 → 만나는 곳 → 준비물 버튼 (`week-04-place-dialog.png`, `week-04-detail-supplies.png`)
5. 시작 시간 굴리기 → 오후 8:30이면 활동 시간이 22시 전에 끝나는 것만 (`week-04-create-errors.png`)
6. 등록 → 바로 공개 / 해 진 뒤 끝나면 관리자 검토
7. (키를 넣은 경우만) 1365 활동 카드 → ‘자세히’ 요약 창 → ‘1365에서 신청하기’(새 탭) · ‘약도’로 창 안 지도+길찾기(지도 모습은 서버에서 확인 후에만 언급)

## 대본 (요지)

> 4주차에는 내 주변 활동을 찾는 기능을 만들었고, 이번에 실제 서비스처럼 다듬었습니다. 활동 찾기에 들어오면 위치를 한 번 묻고, 지도와 목록을 함께 보여줍니다. 거리와 대략 걸리는 시간을 보여주고, 주변에 활동이 없으면 반경을 3km에서 20km까지 알아서 넓힙니다. 활동을 만들 때는 장소를 검색해서 고르는데, 공원이나 카페 같은 열린 공간은 바로 공개되고 요양병원·반려동물 시설 같은 곳은 관리자가 먼저 확인하며 주유소나 술집은 고를 수 없습니다. 이 분류는 서버가 정하고 서명해서 화면에서 바꿀 수 없습니다. 시간은 22시 전에 끝나는 길이만 보여줘서 다시 고칠 일이 없습니다. 그리고 공공데이터의 1365 봉사활동도 같은 지도에 보여주고, 신청은 1365로 연결합니다. 사용자 위치는 검색할 때만 쓰고 저장하지 않습니다.

## 예상 질문

- **1365랑 연동하면 봉사시간도 인정돼요?** 아니요. 1365 활동은 정보만 보여주고, 신청과 실적 인정은 1365에서 합니다. Volink 동네 활동은 실적·보험이 적용되지 않는다고 화면에 계속 안내합니다.
- **장소 분류는 어떻게 해요?** 카카오가 주는 장소 종류(공원, 카페, 요양병원 등)로 서버가 나눕니다. 모르는 종류는 일단 관리자 검토로 보냅니다.
- **API 사용량이 넘으면요?** 1365는 하루 1000회 제한이라 서버가 900회에서 멈추고 저장해 둔 결과만 보여줍니다. 같은 지역 목록은 3시간 동안 다시 부르지 않습니다.

- **공간 인덱스가 뭐예요?** 위치 데이터를 빨리 찾게 해 주는 색인입니다. 전체 활동을 다 계산하지 않고 주변 네모 범위 안의 후보만 먼저 꺼냅니다.
- **위치 정보는 저장해요?** 아니요. 검색 요청에만 쓰고 DB나 로그에 남기지 않습니다.
- **좌표는 어디서 났어요?** 관리자가 지도 앱에서 확인한 좌표를 입력합니다. 현장 이용 허가는 따로 확인해야 합니다.

# 3주차 발표 · 2026-10-13 기준

이번 주는 **화면이 진짜로 저장되기 시작한 주**입니다. 실행 중인 서비스(`http://127.0.0.1:5173`)로 시연합니다. 공개 Pages는 서버가 없어 로그인·저장이 안 되므로 시연에 쓰지 않습니다. 관리자 비밀번호는 시연 PC의 `.env`에만 있습니다.

## 화면 순서 (3분)

| 순서 | 누를 것 | 한마디 |
|---|---|---|
| 1 | 회원가입(일반) → 자동으로 내 활동 → **새로고침** | “가입하면 진짜 저장되고, 새로고침해도 로그인이 유지됩니다.” |
| 2 | 활동 만들기 → ‘사다리 청소’ 등록 | “위험한 활동은 등록 자체가 안 됩니다.” |
| 3 | ‘공원 쓰레기 줍기’ 등록 → 만든 활동 보기 → 활동 찾기 | “문제없는 활동은 바로 공개되고 목록에 뜹니다.” |
| 4 | ‘어르신과 산책’ 등록 → 내 활동 ‘관리자 검토 중’ | “확인이 필요한 활동은 관리자가 보기 전까지 숨겨집니다.” |
| 5 | 로그아웃 → 관리자 로그인 → 관리 → 반려(사유 없이) → 승인 | “반려는 사유가 꼭 있어야 하고, 승인하면 공개됩니다.” |

## 5분 대본

**0:00** “3주차 발표를 시작하겠습니다. 목차는 다음과 같습니다. 회원가입과 로그인, 활동 저장과 위험도 검사, 관리자 확인, 테스트 순서입니다.”

**0:20 (가입·로그인)** “지난주에는 화면에서 검사만 했는데, 이번 주부터 실제로 저장됩니다. 비밀번호는 암호화해서 저장하고, 로그인하면 30분짜리 출입증과 14일짜리 자동 로그인 쿠키를 받습니다. 그래서 새로고침해도 로그인이 유지됩니다. 14세 미만 가입과 관리자 권한 요청은 서버에서도 막습니다.”

**1:20 (위험도)** “활동을 등록하면 서버가 규칙을 다시 검사하고 위험도를 나눕니다. ‘사다리’처럼 위험한 단어가 있으면 등록 자체가 안 되고, ‘어르신’처럼 확인이 필요한 내용이나 해가 진 뒤 끝나는 활동은 관리자 검토로 갑니다. 문제가 없으면 바로 공개됩니다.”

**2:30 (관리자)** “관리자만 관리 메뉴가 보입니다. 기관 확인과 검토 활동을 승인하거나 반려하는데, 반려에는 사유가 꼭 필요하고 모든 처리는 기록으로 남습니다. 기관회원은 관리자가 확인해야 기관 이름으로 활동을 열 수 있습니다.”

**3:30 (테스트)** “서버 테스트 25개와 화면 자동 테스트 16개를 모두 통과했습니다. 테스트 중에 저장된 시각이 9시간 밀리는 오류를 찾아서 고쳤습니다. 테스트 담당이 직접 눌러볼 항목 20개도 정리했습니다.”

**4:20 (남은 것)** “아직 참가 신청은 안 되고, 지도와 거리 검색, 인터넷 배포는 다음 주에 합니다. 장소 좌표도 다음 주에 확정합니다. 감사합니다.”

## 예상 질문 3개

1. **Q. 공개 사이트에서는 왜 로그인이 안 돼요?** — A. 공개 사이트는 서버 없이 화면만 올린 미리보기입니다. 서버를 인터넷에 배포하는 건 4주차입니다. 지금은 실행 중인 서비스로 보여드렸습니다.
2. **Q. 위험 단어만 피하면 위험한 활동도 올라가지 않나요?** — A. 그렇습니다. 단어 검사는 1차로 걸러내는 보조 수단이고, 분야와 종료 시각도 함께 보고 애매한 건 관리자가 확인합니다. 안전을 보증한다고 말하지 않습니다.
3. **Q. 로그인 정보는 안전한가요?** — A. 비밀번호는 원문이 아니라 암호화한 값만 저장합니다. 자동 로그인 쿠키는 자바스크립트로 읽을 수 없게 만들었고, 로그아웃하거나 한 번 쓰면 무효가 됩니다. 로그인 5번 연속 실패하면 1분 동안 막습니다.

**2:50 (지도·목록)** “활동 찾기의 지도 보기입니다. 장소를 누르면 그 장소 활동만 남습니다. 번호는 실제 위치가 아니고, 실제 지도와 반경 검색은 4주차입니다.”

**3:20 (데이터 구조)** “계획서 ERD의 네 묶음을 채워서 테이블이 17개가 됐습니다. 기관, 관심 분야, 알림, 신고와 증빙, 7일 이의제기, 제재 테이블을 새로 넣었고, 사유 없는 관리자 조치나 10MB 넘는 증빙은 DB가 직접 막습니다. 실제 MySQL로 테스트 14개를 돌려 모두 통과했습니다.”

**4:10 (위험 키워드·남은 일)** “위험 키워드 초안은 차단 15개, 검토 17개입니다. 키워드에 안 걸린다고 안전하다는 뜻은 아니고, 검토 대상은 관리자가 마지막에 봅니다. 장소 좌표와 활동 허용 여부는 아직 확인하지 못했습니다. 다음 주에는 로그인, 활동 개설 저장, 위험도 판정을 만들겠습니다. 감사합니다.”

## 예상 질문 3개

1. **Q. 회원가입이 되는 건가요?** — A. 아닙니다. 입력 규칙과 오류 표시만 완성했고, 전송·저장은 3주차 인증 작업에서 만듭니다. 화면에도 ‘준비 중’으로 표시합니다.
2. **Q. 만 14세 확인을 사용자가 거짓으로 입력하면요?** — A. 막을 수 없습니다. 본인 인증을 하지 않으므로 자기 신고 방식이고, 서버에서 다시 계산해 미만이면 가입을 거부하는 수준입니다.
3. **Q. 키워드로 위험한 활동을 다 막을 수 있나요?** — A. 아닙니다. 키워드는 걸러내는 보조 수단입니다. 금지 규칙 → 키워드 → 관리자 확인 순서로 보고, ‘칼국수’처럼 잘못 걸리는 경우는 검토로 넘겨 관리자가 판단합니다.

# 1주차 설계 자료로 발표하기 (보관)

제출한 1주차 보고서는 서비스 흐름·회원 유형·주요 UI·데이터·테스트 **설계**를 정리한 문서입니다. [한 페이지 설계 자료](https://lov22eee.github.io/Volink/design/week01.html)를 열고 위에서 아래로 네 항목을 보여주세요. 서비스 메뉴에는 발표 자료를 넣지 않습니다.

1. 서비스 흐름도: 개설 → 신청 → 승인·대기 → 체크인 → 완료.
2. 회원 권한표: 일반회원·기관회원·관리자와 기관 승인 조건.
3. 주요 화면 구조: 여섯 와이어프레임과 입력·오류 기준.
4. 데이터·API·테스트: 개념 ERD, 예정 경로, 상태 전환·위험 분류·검증 계획.

이 문서는 설계 초안을 보여주며 실제 기능 구현이나 테스트 통과를 뜻하지 않습니다. 아래 실제 서비스 화면은 필요할 때 UI를 설명하는 보조 자료입니다.

## 보여줄 순서

| 순서 | 화면 | 설명할 내용 |
|---|---|---|
| 1 | 활동 찾기 | 주변 활동 목록, 분야·검색어·날짜·유형 필터, 지도·목록 배치 |
| 2 | 활동 카드의 상세 보기 | 일시·장소·정원·시간, 신청→승인/대기→출석→완료 흐름 |
| 3 | 활동 만들기 | 자율·기관 주관 활동 구분, 2~10명·3시간 이내 입력 기준 |
| 4 | 내 활동 | 신청·개설·활동 기록을 구분하는 화면 구조 |
| 5 | 로그인·회원가입 | 일반회원과 기관회원의 입력 차이, 기관 확인 후 주관 활동 개설 |
| 6 | 필요할 때 문서 | README와 architecture.md의 데이터·권한·테스트 설계 |

지도·로그인·가입·신청·기관 승인·저장·완료 기록은 아직 연결되지 않았습니다. 예시 활동이나 입력 화면을 실제 업무 기능의 완성으로 설명하지 않습니다. 발표 자료와 인수인계는 docs에 두고 서비스에는 이용 메뉴만 둡니다.
