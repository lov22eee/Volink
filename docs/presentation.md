# 1주차 설계 자료로 발표하기

제출한 1주차 보고서는 서비스 흐름·회원 유형·주요 UI·데이터·테스트 **설계**를 정리한 문서입니다. [한 페이지 설계 자료](https://lov22eee.github.io/Volink/design/week01.html)를 열고 위에서 아래로 네 항목을 보여주세요. 서비스 메뉴에는 발표 자료를 넣지 않습니다.

1. 서비스 흐름도: 개설 → 신청 → 승인·대기 → 체크인 → 완료.
2. 회원 권한표: 일반회원·기관회원·관리자와 기관 승인 조건.
3. 주요 화면 구조: 여섯 와이어프레임과 입력·오류 기준.
4. 데이터·API·테스트: 개념 ERD, 예정 경로, 상태 전환·위험 분류·검증 계획.

이 문서는 설계 초안을 보여주며 실제 기능 구현이나 테스트 통과를 뜻하지 않습니다. 아래 실제 서비스 화면은 필요할 때 UI를 설명하는 보조 자료입니다.

## 보여줄 순서

| 순서 | 화면 | 설명할 내용 |
|---|---|---|
| 1 | 활동 찾기 | 주변 활동 목록, 분야·검색어·날짜·유형 필터, 지도·목록 배치 |
| 2 | 활동 카드의 상세 보기 | 일시·장소·정원·시간, 신청→승인/대기→출석→완료 흐름 |
| 3 | 활동 만들기 | 자율·기관 주관 활동 구분, 2~10명·3시간 이내 입력 기준 |
| 4 | 내 활동 | 신청·개설·활동 기록을 구분하는 화면 구조 |
| 5 | 로그인·회원가입 | 일반회원과 기관회원의 입력 차이, 기관 확인 후 주관 활동 개설 |
| 6 | 필요할 때 문서 | README와 architecture.md의 데이터·권한·테스트 설계 |

지도·로그인·가입·신청·기관 승인·저장·완료 기록은 아직 연결되지 않았습니다. 예시 활동이나 입력 화면을 실제 업무 기능의 완성으로 설명하지 않습니다. 발표 자료와 인수인계는 docs에 두고 서비스에는 이용 메뉴만 둡니다.
