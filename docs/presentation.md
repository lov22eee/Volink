## 1주차 · 약 3~5분

백엔드·MySQL·프론트엔드를 시작한 뒤, 서비스 왼쪽 아래 **‘1주차 실행 화면 발표’**를 누릅니다. 브라우저 주소의 경로는 `/#/presentation`입니다. ‘이전/다음’ 또는 하단 점 버튼으로 4장 전환합니다. 이 자료는 실제 추가 구현 내용을 설명하며 이미 제출한 보고서의 기간 내 구현 실적과 구분합니다.

| 순서 | 보여줄 화면 | 설명할 내용 |
|---|---|---|
| 1 | 발표 1장 | 지역 주민의 2~10명·3시간 이내 활동을 연결하는 서비스 목적 |
| 2 | 발표 2장 | 화면·서버·데이터의 1주차 완료 항목 |
| 3 | 서비스 홈 | MySQL에서 읽은 장소·활동 시안, 분야·검색어 UI 필터, 상세 창 |
| 4 | 활동 만들기 | 입력 항목·정원 2~10·180분 이내·안전 안내, 서버 저장은 미구현 |
| 5 | 사용자 흐름 / 진행 현황 | 역할·소유관계 설계, 페르소나 9명, 현재·향후 범위 |
| 6 | 발표 3장 | React→Spring Boot→MySQL 연결과 현재 연결 상태 |
| 7 | 발표 4장 | 2주차 담당자가 이어갈 명세·데이터·설계 작업 |

강조할 구분: **지금 동작하는 것은 환경·읽기 API·화면 초안**입니다. 신청, 위험 판정, 지도, QR, 공식 봉사 인증이 동작한다고 설명하지 않습니다. 공식 실적·종합보험 비적용 안내를 화면에 표시합니다.

## 자료

- `docs/screenshots/`: 실제 실행 후 브라우저 검증으로 생성한 1주차 화면.
- `docs/reports/week-01.md`: HWP 보고서 항목에 붙여 넣을 문장.
- `docs/architecture.md`: ERD·화면 흐름도·권한 초안.

## 이후 주차

그 주에 구현한 실제 기능을 발표 화면에 추가하고 README의 완료 표시·인수인계와 함께 갱신합니다. 고정된 ‘1주차’ 발표 화면이 새 기능까지 완료된 것처럼 보이지 않게 주차·문구를 바꿉니다. 보고서는 성공한 검증과 미완료를 구분하고, 다른 사람이 만든 결과를 자신이 새로 구현한 것으로 기록하지 않습니다.
