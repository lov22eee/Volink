## 금주 작업 사항

~~~text
1. 서비스 구조 및 사용자 흐름 설계
   Volink의 활동 개설, 참가 신청, 승인, 대기, 체크인, 완료까지의 전체 이용 흐름을 정리하고 주요 화면과 기능 구성을 설계하였다.

2. 회원 유형 및 권한 구조 설계
   회원 유형을 일반회원, 기관회원, 관리자로 구분하였다. 일반회원은 자율 활동을 개설하고, 기관회원은 기관 확인 후 기관 주관 활동을 등록할 수 있도록 구성하였으며 관리자는 기관 승인과 활동 관리 기능을 담당하도록 설계하였다.

3. 주요 화면의 UI 구조 설계
   활동 찾기, 활동 상세, 활동 만들기, 내 활동, 로그인·회원가입 화면의 UI 구조를 설계하였다. 활동 목록과 지도 레이아웃, 검색 필터, 모집 인원 및 활동 시간 등 입력·오류 처리 기준을 정리하였다.

4. 서버·데이터 및 테스트 구조 설계
   사용자, 활동, 참가 신청, 체크인, 완료 기록 등을 기준으로 ERD와 API 구조를 정리하고 참가 상태 전환 및 권한 기준을 설계하였다. 또한 시연용 장소와 사용자 데이터, 위험 활동 분류 및 기본 테스트 항목을 정리하였다.
~~~

## 다음주 작업 예정 사항

~~~text
1. 주요 프론트엔드 화면 구현
   활동 찾기, 활동 상세, 활동 만들기, 내 활동, 회원가입 화면을 React 기반으로 구현하고 샘플 데이터를 이용하여 화면 흐름을 확인한다.

2. 회원 역할별 화면 구현
   일반회원과 기관회원의 가입 화면을 구분하고 기관 승인 대기·승인 완료 상태와 자율 활동·기관 주관 활동을 화면에서 구분할 수 있도록 구현한다.

3. 서버 및 데이터베이스 기본 환경 구성
   Spring Boot와 MySQL 기반 개발 환경을 구성하고 사용자, 기관, 활동, 참가 신청 등에 필요한 기본 테이블과 API 구조를 작성한다.

4. 시연 데이터 및 테스트 준비
   시연용 활동과 역할별 모의 계정을 구성하고 중복 신청, 정원 초과, 권한 오류, 위험 활동 등 핵심 기능 검증을 위한 테스트 케이스를 구체화한다.
~~~

## 제출 후 작업과 구분

10월 7~8일 추가한 실행 환경·React 화면·검증·배포 설정은 이 보고서의 제출 기간 내 완료 실적으로 소급하지 않습니다. 10월 8일에는 위 설계를 설명할 실제 서비스 형태의 UI를 정리했으며, 로그인·신청·기관 승인 등의 서버 업무 기능은 아직 구현하지 않았습니다. 현재 상태는 README와 [화면 대응·검증 기록](../service-ui-week01.md)을 참고하세요.
