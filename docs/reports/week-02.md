## 전주까지 개발 현황

```text
1. 이전 주까지 동작하는 화면·기능·환경의 누적 현황:
   React·Vite 서비스 화면 6개(활동 찾기·상세·만들기·내 활동·로그인·회원가입)와 Spring Boot·MySQL·Flyway 개발 환경을 구성했다. 시연 활동 3건·장소 후보 3곳을 DB에서 읽어 화면에 표시하며, 화면만 담은 단일 HTML과 GitHub Pages 공개 화면을 준비했다.
2. 이전 주 검증 결과 및 아직 해결되지 않은 문제:
   DB 제약(정원 2~10명·3시간·중복 신청·수동 체크인 사유) 통합 테스트와 화면 테스트가 통과했다. 기관회원 테이블·회원 유형, 장소 좌표·활동 허용 여부, 로그인·저장 기능은 없었다.
3. 이번 주 작업이 이어받은 데이터·명세·코드:
   1주차 ERD·권한·상태 전이 초안, V1·V2 마이그레이션, 서비스 화면 코드, 제출 보고서의 일반회원·기관회원·관리자 설계.
```

## 금주 작업 사항

```text
1. 이번 주 실제 구현·수정한 화면 및 사용자 동작:
   활동 만들기·회원가입·로그인에 입력 규칙과 칸별 오류 표시(고칠 항목 수, 첫 오류 칸 이동)를 넣었다. 회원가입에 생년월일(만 14세 미만 가입 불가)·관심 분야(1~3개)·기관 확인 3단계 안내를 추가했다. 활동 찾기 지도 보기에서 장소를 고르면 목록이 좁혀지도록 지도·목록 배치를 정리했고(실제 지도는 미연동), 자율/기관 주관 활동 유형 필터와 내 활동의 신청 상태 안내를 추가했다. 가입·개설 정보는 전송·저장하지 않는다.
2. 이번 주 실제 구현·수정한 API·DB·권한·규칙:
   V3 마이그레이션으로 회원 유형·생년월일, 기관(확인 대기·완료·반려), 관심 분야, 알림, 신고·증빙, 7일 이의제기, 제재, 관리자 조치 기록, 위험 키워드 초안(차단 15·검토 17) 테이블과 제약을 추가했다(업무 테이블 17개). 3~7주차 API 목록·오류 형식·화면별 요구사항, 회원 유형별 권한표, 신청·활동·기관·신고 상태 전이(거절·재신청·보류 복원·제안 자리 정원 포함)를 확정했다. 보안(비밀번호 해시·JWT·요청 제한·파일·위치) 및 비용 기준을 정했다.
3. 실행한 검증·발견/수정한 오류·발표 자료·미완료 사항:
   실제 MySQL 백엔드 테스트 14개 통과, 전체 서비스 연결 확인 통과, 브라우저 테스트 12개 통과(2026-10-11). 오류 문구가 입력칸 이름에 섞여 읽히는 접근성 문제를 발견해 수정했다. 2주차 한 장 요약(design/week02.html)과 발표 대본을 작성했다. 장소 좌표·활동 허용 여부는 현장·관리기관 확인이 필요해 미완료이며, 로그인·저장·위험도 판정 등 업무 기능은 미구현이다.
```
