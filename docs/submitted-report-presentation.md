# 제출 보고서 기준 발표 · 2026.10.06 파일

기준: 사용자가 이미 제출한 `Volink_(오준원,박용빈,김병수)_진행보고서_20261006.hwp`.

보고서 작업기간은 **2026.09.28 ~ 2026.10.05**이며, 전주까지 개발 현황은 비어 있습니다. 이번 발표는 그 기간의 **설계 내용**을 설명합니다. 10월 7일에 추가한 실제 개발 기반과 UI 초안을 제출 기간의 구현 실적으로 소급하지 않습니다.

## 가장 간단하게 발표하기

1. [발표 HTML](../frontend/public/presentations/report-20261006.html)을 저장합니다.
2. 파일을 Chrome·Edge 등 브라우저로 엽니다. **서버·MySQL·인터넷이 필요 없습니다.**
3. ‘전체화면’ 버튼을 누르고 하단 ‘이전/다음’으로 진행합니다.
4. ‘발표 대본 보기’를 누르면 현재 슬라이드의 설명 문장이 나옵니다.

PDF로 발표하려면 [7장 발표 PDF](slides/Volink_제출보고서_발표_20261006.pdf)를 사용하세요. PDF에는 대본·조작 버튼을 제외한 슬라이드만 포함됩니다. HTML의 UI 탭 전환은 PDF에서는 사용할 수 없습니다.

서비스를 실행한 경우에도 왼쪽 아래 **‘제출 보고서 발표’** 메뉴로 같은 자료를 엽니다. 기존 ‘1주차 실행 화면 발표’는 실제 구현 기반을 보여주는 별도 자료로 유지했습니다.

## 짧은 발표 대본

**1장.** “이번 주에는 기능 구현에 앞서 서비스의 구조와 사용자 흐름, 회원 유형과 권한, 주요 화면, 서버·데이터·테스트 구조를 설계했습니다. 제출한 9월 28일부터 10월 5일까지의 내용을 기준으로 발표하겠습니다.”

**2장.** “활동 개설부터 참가 신청, 승인 또는 대기, 현장 체크인, 완료 기록까지 이어지는 흐름을 정리했습니다. 승인은 정원이 있으면 확정, 없으면 대기로 분기합니다. 실제 상태 변경 서비스는 이후 구현할 예정입니다.”

**3장.** “일반회원은 자율 활동을 개설하고, 기관회원은 기관 확인 후 기관 주관 활동을 등록하도록 설계했습니다. 관리자는 기관 승인과 활동 관리를 담당합니다. 기관회원과 승인 기능은 현재 설계 단계이며 기존 코드에는 아직 적용하지 않았습니다.”

**4장.** “활동 찾기, 상세, 만들기, 내 활동, 로그인, 회원가입의 UI 구조를 정리했습니다. 메뉴를 바꿔 화면 배치를 보여드리겠습니다. 지도·목록과 검색 필터를 함께 놓고, 정원과 활동 시간에는 입력·오류 기준을 두었습니다. 로그인·기관 상태 표시는 설계 예시입니다.”

**5장.** “사용자·활동·참가 신청·체크인·완료 기록을 중심으로 데이터와 API 구조를 정리했습니다. 신청 상태를 중심으로 출석과 완료를 연결하고 본인, 자기 활동의 개설자, 관리자 접근 범위를 구분합니다. 기관 관련 테이블·승인 구조와 최종 API 명세는 추가 확정이 필요합니다.”

**6장.** “시연용 장소와 사용자 데이터를 정리하고, 중복 신청, 정원 초과, 권한 오류, 위험 활동 검증 항목을 준비했습니다. LOW는 게시, REVIEW는 검토 전 비공개, BLOCKED는 차단으로 설계했습니다. 여기서 설명하는 것은 테스트 기준이며 업무 기능의 검증 완료 결과가 아닙니다.”

**7장.** “다음 주에는 주요 화면과 회원 역할별 화면을 React로 구현하고 샘플 데이터로 흐름을 확인하겠습니다. Spring Boot·MySQL 기반과 사용자·기관·활동·참가 구조를 준비하고 역할별 시연 데이터와 테스트 케이스를 구체화하겠습니다.”

## 현재 코드와 다른 부분

- 제출본에는 **기관회원·기관 승인·기관 주관 활동**이 추가돼 있습니다. 현재 백엔드는 USER/ADMIN 및 활동 개설자 소유관계 기반 초안이며 기관 테이블·가입·승인 API는 없습니다.
- 로그인·회원가입·내 활동은 이번 발표의 **와이어프레임**입니다. 사용자 인증이나 활동 저장·신청이 동작하지 않습니다.
- 서버·DB 환경은 제출본에서 **다음주 계획**입니다. 현재 저장소에 추가된 실행 환경을 제출 기간 내 완료 항목으로 바꾸어 설명하지 않습니다.
- 기관 승인 자체가 공식 봉사실적 인증 또는 보험 적용을 의미하지 않습니다.
- 기존 `docs/reports/week-01.md`는 AI가 작성한 참고 초안입니다. 이미 제출한 보고서와 같은 문서로 취급하지 않습니다.
- 후속 담당자는 기관 정보·승인 상태·기관 주관 활동의 권한·데이터 구조를 2주차 명세에서 확정해야 합니다. 발표 시안 추가로 해당 업무 기능을 완료 체크하지 않습니다.

## 재생성

프론트 의존성과 Chromium이 준비돼 있을 때:

```bash
cd frontend
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run report:export
```

개인 PC에서는 Playwright Chromium 설치 후 경로 변수 없이 `npm run report:export`를 사용합니다. PDF와 표지·회원 권한·UI 시안 캡처 3장을 갱신합니다.
