## 발견·수정

- **동시 승인 버그(중요):** 마지막 1자리에 승인 10건을 동시에 보내자 10건이 모두 확정됐습니다. 활동 행을 `FOR UPDATE`로 잠갔지만, MySQL 기본 격리 수준(REPEATABLE READ)은 잠금 전에 만든 스냅샷으로 인원을 셉니다. 신청 처리 트랜잭션을 READ COMMITTED로 바꾼 뒤 1건만 확정되고 9건은 `CAPACITY_FULL`이 됐습니다.
- **시각 9시간 차이:** 신청 시각·알림 시각·기관 신청 시각(3주차)이 UTC로 보였습니다. TIMESTAMP 컬럼만 한국 시간으로 바꿔 보여주는 `Sql.kst()`를 추가하고 알림 시각 테스트를 넣었습니다.
- **4주차 `check-dev.sh`:** 브라우저 테스트가 장소 좌표를 넣은 뒤에는 ‘모든 장소 UNVERIFIED’ 확인이 실패했습니다. ENTERED도 허용하도록 4주차 브랜치에서 고쳤습니다.
- 예시 활동 상세의 버튼 문구가 바뀌어 화면 테스트 2개(서비스·오프라인)의 기대 문구를 맞췄습니다.

## 관찰 중

- 한 번의 느린 전체 실행(1.2분)에서 ‘검토 활동은 관리자 승인 전 숨김’ 화면 테스트가 실패했습니다. 오류 기록을 남기지 못했고, 단독 실행과 이후 전체 실행 2회는 통과했습니다. 원인을 확정하지 못해 관찰 중입니다.

## 실행하지 않은 것

- 실제 1분 스케줄러 동작: 테스트에서는 꺼 두고 같은 처리 함수(`expireDue`)를 직접 불러 확인했습니다. 배포 서버에서 6시간 제안이 실제로 만료되는지는 확인하지 않았습니다.
- 배포 서버 반영, 테스트 담당 직접 확인([목록](manual-test-week05.md)).
